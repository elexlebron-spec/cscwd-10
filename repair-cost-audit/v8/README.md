## Actual scalar cost interface

This revision examines released pytest-split0.11.0 with pytest8.4.2. The unchanged plugin stores native per-test setup/call/teardown durations; its unchanged algorithms sum them as final group-load estimates. Documentation recommends whole-suite profiling for distributed runs, including order-sensitive legacy suites. An independent [public user report](https://github.com/pytest-dev/pytest/issues/8741) describes expensive database setup attributed to the first test and resulting partition imbalance. The reporter's project is unavailable; our experiment validates the interface on a constructed FE validation suite.

The new finding concerns the meaning of a scalar cost across contexts. Pooled attribution can fit every measured item exactly and still undercount a new process's shared fixture activation. Isolated profiles can instead overcount sharing. The audit separates this representation loss from greedy partitioning loss by independently enumerating all matched feasible partitions and the best scalar-optimal face. Shared setup, fixture profiling, grouping, union mathematics and generic optimization are prior art.
